# Pro Model Checkpoints

Eternity should periodically ask the user to consult 5.5 Pro or the current best Pro reasoning model when the project enters unknown territory.

## When To Ask

Ask for a Pro checkpoint before:

- Locking in a difficult scientific model.
- Making a major architecture decision that future work will depend on.
- Interpreting a surprising or counterintuitive simulation result.
- Treating a mechanism as potentially novel.
- Moving from one project phase to the next.
- Continuing after repeated validation failures.

## How To Ask

Use this exact heading in chat:

```text
Pro checkpoint recommended
```

Then include:

- Why this is a checkpoint.
- What decision needs outside reasoning.
- What context the Pro model needs.
- A compact paste-ready prompt.

## How To Record Input

When the user brings back Pro-model guidance, summarize the decision in the relevant roadmap, plan, or research note. If it affects code behavior or scientific assumptions, add a test or explicit validity note where practical.
